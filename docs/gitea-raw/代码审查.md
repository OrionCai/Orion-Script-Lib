### 问题清单

#### 🔴 严重问题

**问题 1：支持通过 URL 查询参数传递私有仓库访问 Token**

- 位置：`Cloudflare/gitea-raw/worker.js:401-407`
- 问题：允许 `?token=...`，同时 `wrangler.toml:10-14` 启用了持久化 invocation logs。URL 可进入 Cloudflare 请求日志、浏览器历史、代理日志、截图和 Referer。
- 风险：Token 一旦泄漏，可读取所有白名单内的私有仓库，而不只是单个文件。
- 建议：移除 query token，只接受 `Authorization: Bearer ...`；同时轮换任何已经出现在 URL 中的 Token，并检查/清理日志保留策略。

**问题 2：私有文件响应被声明为可公共缓存**

- 位置：`Cloudflare/gitea-raw/worker.js:141`、`Cloudflare/gitea-raw/worker.js:156-162`、`Cloudflare/gitea-raw/worker.js:378-395`
- 问题：公开和私有文件共用 `Cache-Control: public, max-age=60`，而 Bearer 请求的 URL 不包含用户凭据，响应也没有区分 `Authorization`。Worker 内部虽然在读 Cache API 前先做了鉴权，但 `public` 会明确允许浏览器、共享代理或额外 CDN 层存储私有内容。
- 风险：如果 Worker 外层存在共享缓存规则，未鉴权请求可能不再进入 Worker，直接命中已授权用户的响应。
- 建议：公开和私有响应分开策略。私有文件使用 `Cache-Control: private, no-store`并禁用 Cache API；如确实需要边缘缓存，必须保证所有请求一定先执行 Worker 鉴权，且不向下游发送 `public` 缓存语义。

#### 🟡 建议修改

**问题 3：Raw 域名可直接执行仓库中的主动内容**

- 位置：`Cloudflare/gitea-raw/worker.js:26-44`、`Cloudflare/gitea-raw/worker.js:378-395`
- 问题：`.html` 会以 `text/html` 返回，`.js` 会以 JavaScript 返回，未设置 CSP、`X-Content-Type-Options: nosniff` 或 `Content-Disposition`。
- 风险：拥有任一允许仓库写权限的人可在 Raw 域名上发布可执行页面。如果 Raw 域名与 Gitea 共享父域 Cookie 或被视为可信域名，可引入 XSS/钓鱼/同站 CSRF 风险。
- 建议：Raw 服务使用无 Cookie 的独立站点；若不需要在浏览器执行 HTML，将 HTML 作为 `text/plain` 或附件下载，并增加 `nosniff`。

**问题 4：没有应用层限流与鉴权失败保护**

- 位置：`Cloudflare/gitea-raw/worker.js:50-173`
- 问题：每个来源都可以无限请求公开文件或尝试私有 Token。
- 建议：在 Cloudflare WAF/Rate Limiting Rules 中按 IP 限流，对 401 密集的请求使用更严格阈值。

**问题 5：代码允许通过明文 HTTP 连接 Gitea**

- 位置：`Cloudflare/gitea-raw/worker.js:276-298`
- 问题：`GITEA_URL` 同时允许 HTTP 和 HTTPS。当前配置是 HTTPS，但未来误配为 HTTP 时会以明文发送 `GITEA_TOKEN` 和私有文件。
- 建议：生产环境只允许 `https:`，本地开发如有需要再以显式开关放行 HTTP。

#### 🟢 可选优化

**问题 6：安全边界缺少回归测试**

- 位置：`Cloudflare/gitea-raw/worker.test.js`
- 建议：增加私有响应不可公共缓存、不支持 query token、安全响应头、仓库由 public 改为 private 后的缓存撤销测试。

### 实现中已有的安全措施

- 私有仓库在读取 Worker Cache API 前会校验外部 Token。
- Gitea Token 只发送给判定为私有的仓库，不会发送给公开仓库。
- 仓库白名单、路径拒绝与 URL 分段编码降低了 IDOR 和路径穿越风险。
- Token 使用 SHA-256 后定长比较，密钥通过 Worker Secret 管理，没有写入仓库。
